## Phạm vi và giới hạn

Quét 15 trang chính: /, /rooms, /devices, /camera, /cultivation, /alerts, /sessions, /issues, /harvests, /harvest-requests, /reports, /orders, /packages, /users, /settings; đo DOM và computed CSS tại 1920×1080 và 1366×768.

Kiểm tra sâu sidebar ở hai bảng chính; mở Drawer phiên, Tổng quan và Lịch sử IoT; mở Modal thêm giống nấm nhưng không lưu. Mô phỏng API chậm 4 giây, danh sách rỗng, HTTP 500, ngày epoch, nhân viên không tra được, HTTP 403 của lịch sử kiểm tra. Đã gỡ route mock và đưa trình duyệt về dữ liệu thật.

Đây là audit giao diện trên dữ liệu và các luồng nêu trên, không phải chứng nhận mọi tab/modal/role. Chưa chạy đầy đủ các tab báo cáo, camera live, upload, mọi bộ lọc, mất mạng kéo dài và telemetry tải lớn. Lượt quét ban đầu chờ 2,3 giây/trang: /sessions chưa hiện bảng do tải bổ sung; đã kiểm tra lại sau khi danh sách tải xong. Một số request từ trang trước vẫn hoàn tất sau navigation, nên kết luận N+1 dùng thêm lượt đo riêng.

## 4. Network và Console

**[Critical C1 — Lỗi dữ liệu phụ làm mất toàn bộ danh sách phiên]**

- Lượt đo riêng: chỉ mở /sessions với 13 phiên đã có **41 GET API**: 1 danh sách, 1 thông báo, **39 request lịch sử/tiến độ**. Chưa mở Drawer hoặc tab lịch sử.
- [admin-session.api.ts:59](../src/features/sessions/api/admin-session.api.ts) await withFarmGrowth trước khi trả danh sách.
- [farm-growth.api.ts:7](../src/features/sessions/api/farm-growth.api.ts): mỗi phiên gọi spawn-inspections, daily-inspections, progress; dòng 25 gom Promise.all theo nhóm 4. Một request lỗi làm reject cả danh sách. Chi tiết phiên cũng chạy withFarmGrowth tại admin-session.api.ts.
- Thử nghiệm 403 chỉ trên lịch sử: UI hiện “Không thể tải danh sách phiên canh tác...” và mất toàn bộ bảng dù API danh sách thành công. Lỗi này cũng có phạm vi ảnh hưởng tới các trang tái dùng API sessions; runtime thấy request bổ sung ở Rooms/Orders.
- Đề xuất: trả/render danh sách chính độc lập, dùng summary đã có từ API chính; tải lịch sử trong tab liên quan. Nếu summary backend chưa đủ, bổ sung endpoint summary/batch có kiểm soát thay vì N×3 request. Lỗi dữ liệu phụ phải giới hạn ở panel tương ứng.

**[Major M5 — Tab IoT tải lại cùng URL khi metadata tầng cập nhật]**

- Đã lặp lại trên một phiên tải trang mới: khi bấm “Lịch sử IoT”, URL environment-history/sessions/22 có from/to/page=1/pageSize=100 bị gọi **2 lần**, URL cùng phiên không có from/to cũng **2 lần**; tất cả trả 200. Đây không phải retry do HTTP lỗi, và không coi hai URL khác nhau là cùng một request.
- [SessionIoTHistoryTab.tsx:206](../src/features/sessions/components/SessionIoTHistoryTab.tsx): tải floorMappings; các map/label dùng kết quả này. [useSessionEnvironmentHistory.ts:218](../src/features/sessions/hooks/useSessionEnvironmentHistory.ts) và dòng 319 đưa signature map/scope vào query key dù URL server không đổi.
- Nguồn phù hợp với hiện tượng metadata làm query key thay đổi; cần instrument key trước/sau trong bản vá để chốt toàn bộ nguyên nhân.
- Đề xuất: cache bản ghi mạng theo session/range/pagination; map/lọc dữ liệu tầng qua select hoặc lớp trình bày ổn định. Giữ chart/table là hai phạm vi dữ liệu khác nhau khi nghiệp vụ cần. Không chỉ tắt StrictMode để che request.
- Điểm đạt: chưa gọi environment-history khi mới mở Drawer Tổng quan; component/tab IoT chỉ tải sau khi chọn. Lịch sử kiểm tra vẫn bị kéo sớm qua C1.

**[Minor N1 — Console có cảnh báo Ant Design deprecated]**

- Drawer width: Devices/Alerts/Orders; Modal maskClosable: Packages/Users; Alert message: Settings.
- Vị trí tiêu biểu: [DeviceControlPanel.tsx:743](../src/pages/devices/components/DeviceControlPanel.tsx), [AlertsPanel.tsx:404](../src/features/alert-center/components/AlertsPanel.tsx), [MushroomVarietyFormModal.tsx:349](../src/pages/packages/components/MushroomVarietyFormModal.tsx), [SendResetOtpModal.tsx:68](../src/pages/users/components/SendResetOtpModal.tsx), [ThresholdProfileTab.tsx:167](../src/pages/settings/components/ThresholdProfileTab.tsx).
- Đề xuất: chuyển prop sang API Ant Design tương ứng với phiên bản đã cài, kiểm tra overlay không đổi kích thước ngoài ý muốn.
- Trong lượt quét bình thường không ghi nhận pageerror, hydration error hoặc HTTP API lỗi. Console 500/403 ở các lượt mock là lỗi được chủ động tạo để kiểm thử, không tính là lỗi server thật. Request polling thông báo không tự động bị coi là request trùng.
